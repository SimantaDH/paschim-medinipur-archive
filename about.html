Project & About

About the Project

What this archive is for, what it set out to do, and how it was actually built.

Project Brief

Why this archive exists

As residents of Paschim Medinipur, preserving Gajan and Patachitra felt like a responsibility rather than a research topic. Most existing scholarship on Gajan leans on visual ethnography — what the ritual looks like from the outside — while the lived experience and oral narrative of the people inside it stays largely undocumented. Patachitra, meanwhile, already has a sprawling digital footprint: government portals, artist pages, art-market listings, press coverage, social video — more than two dozen separate registers that rarely talk to each other. This project turns oral tradition into a sustainable digital archive by pairing ethnographic fieldwork with careful digital preservation, treating both traditions as living practice rather than finished heritage.

Project Objectives

Five things this project set out to do

01

Document & archive both traditions

Build a digital record of Gajan and Patachitra that treats each as a living, changing practice, not a frozen artifact.

02

Build a sustainable, community-centred repository

Use fieldwork, oral history and audiovisual records as the foundation — not scraped or secondhand material.

03

Preserve local voices through participatory archiving

Let the people who practise these traditions speak for themselves, in their own words, wherever possible.

04

Put Digital Humanities method to work

Apply DH tools — structured metadata, digital-footprint mapping, citation infrastructure — to safeguarding intangible heritage.

05

Make it genuinely accessible

Bilingual (Bengali/English), screen-reader- and narrator-friendly, adjustable text size, dark/light mode — built to actually support research and community engagement, not sit in a folder.

How We Built It

Method, stack and the constraints we kept on purpose

Fieldwork

Key-informant interviews were the backbone of both tracks. For Gajan: five participants across five roles — a migrated villager, a devotee of fifty years, a temple priest, a young observer, and an active ritual performer. For Patachitra: interviews and field documentation across five comparable roles — a master patua/collective president, a senior woman performer, a next-generation artisan, a market-facing patua and a community organiser — plus a literature review spanning twenty-seven articles.

Documentation

Audio and video recordings preserve the participants' own voices and, where captured, their manner of narration; written transcription makes that material searchable and citable. Culturally specific terms — Jhiv Phora, Ban Phora, Hobishya, Bhokta, Sannyasi, Thakur Tola, Charak Kath — are explained in context rather than flattened into generic translation.

Technical build

This site is a plain static HTML/CSS/JS build — no framework, no server, no database — so it can be hosted on GitHub Pages indefinitely without a dependency silently breaking. Real browser-native tools do the heavy lifting: the SpeechSynthesis API narrates the page aloud, the Web Audio API synthesizes the ambient soundscape entirely in-browser (no sampled or copyrighted audio), and Google Translate's embed handles Bengali/English switching.

Real WebXR, not a substitute

The AR/VR mode under Explore runs on the browser's own navigator.xr WebXR API via three.js — genuine augmented- and virtual-reality sessions, not a CSS imitation. It needs no server: WebXR runs entirely client-side over HTTPS, which GitHub Pages already provides. Both scenes are built as original procedural 3D geometry and hand-painted canvas textures — a Gajan ritual space (charak wheel, dhak, trishul, a live particle flame) and a Patachitra scroll-painting scene (pigments, brush, an unrolling scroll) — so the painting and ritual stay the project's own work rather than a borrowed photograph or a licensed 3D asset. On a phone or headset without WebXR, the full interactive 3D scene still works with mouse or touch; the AR/VR buttons simply activate for real when a capable device is detected.

Every audio file on this site is a real field recording from the project's own interviews, compressed for low file size without re-recording or synthesizing the voices themselves.
